# 数字和关系的准确含义

## 输入

V8 快照包含 metadata、扁平 nodes/edges 数组和 strings 表。解析器以 node_fields/edge_fields 定位列，边目标使用原始节点数组偏移并验证对齐。节点 ID 使用 UInt64 校验并保留十进制字符串，最大支持 18446744073709551615；字节数合计限制为 9007199254740991。

拒绝重复 ID/JSON 键/字段名、越界字符串、无效边目标、不一致数量、缺失字段、未知边类型、负数和非整数记录。多余的数值列可存在；V8 13.x 可能多给出一个未对应字段的类型描述，解析器允许这种尾随描述，记录宽度仍严格由字段数决定。没有声明自定义根时使用第一个节点，根必须是 synthetic。

trace_tree、locations 等可选信息本版本不做归因分析。输入必须是完整的 V8 堆快照，不支持 .heapprofile 采样文件或 JVM HPROF。

## snapshot-strong-v1

对一条边 source → target：

1. weak 边不参与保留关系。
2. self 边不参与，避免自引用产生虚假路径。
3. shortcut 只在 source 是根时参与。
4. property/context/internal/element/hidden 的其余边参与。

所有原始边仍可查询，`retaining` 字段标明是否用于算法。

**WeakMap 是明确的限制。**V8 会使用带有 `part of key` 与 `WeakMap` 的 internal 边描述条件关系。MoonHeap 识别并统计这些边，但仍将它们作为普通保留图边计算。真实 GC 的 ephemeron 规则不能简化为一般强边，所以相关保留体积只是当前图策略的结果，可能与实际回收行为不同。

Chrome DevTools 还采用页面归属、调试器引用和 WeakMap 等专用处理。MoonHeap 不实现所有这些启发式规则，也不会把不可达节点重新挂到根上。因此不承诺与 Chrome 的每一项 retained size 一致。本项目没有借用 Chrome 的实现代码。

## 可达性、支配关系与保留体积

根可达性与最短路径使用广度优先遍历。路径只是多条可行路径中的一条，不代表唯一持有者。

若从根到 v 的所有路径都经过 d，则 d 支配 v。直接支配者形成支配树。一个对象的 retained bytes 等于其支配子树中所有节点的 self_size 之和，包含自身；直观上是从图中删掉该节点后，原本可达而变为不可达的字节数。

例：root → A、root → B、A → shared、B → shared。A 和 B 都不单独支配 shared；不能把 shared 的体积同时归入 A 和 B。若 A 和 B 形成环，环本身也不意味着泄漏，仍需分析到根的外部路径。

实现使用非递归 DFS 和 Cooper–Harvey–Kennedy 支配迭代，避免深链递归栈溢出。算法有独立工作预算，超限明确报错而非返回部分估算。最坏情况下迭代算法并非线性时间；默认预算限制工作量，不限制实际墙钟时间。

从根不可达的对象：shallow bytes 仍计入总览和分组；retained bytes、root distance、immediate dominator 为空。根自身没有直接支配者。

## 汇总与比较

浅体积是快照 self_size 原值，不是 RSS、浏览器总占用或完整 native memory。底层引擎如何报告外部内存会影响结果。

同名对象按 `kind + name` 分组。这是调查用聚合，不是类加载器/Realm/模块级身份。汇总相加 shallow bytes，单独提供 max_retained_bytes，不相加可能重叠的支配子树。

aggregate 比较适用于不同进程：只比较每个分组的对象数和浅体积。

identity 比较依赖使用者确认两个输入来自**同一 V8 isolate 的相应快照序列**；同一操作系统进程里也可能存在多个 isolate。不能仅凭文件名、相同 Node 版本、相近 ID 或生成时间推断这一点。重复 ID 若类型或名称矛盾会报错，但没有矛盾并不构成来源证明。此模式报告 ID 存在、消失及 self_size 变化，不输出“确认泄漏对象”。

新增对象可能是正常缓存、预热或业务需求。应比较重复操作与清理行为，并检查实际引用所有者后再判断。

## 资源边界

| 限制 | 默认值 |
|---|---|
| CLI / 网页输入文件 | 每份 64 MiB，最多同时 2 份 |
| 库 max_chars | 67,108,864 个 String.length() 单位 |
| 节点 | 1,000,000 |
| 边 | 8,000,000 |
| 字符串条目 | 2,000,000 |
| 支配计算工作预算 | 200,000,000 |
| 路径长度 | 1024，可由调用者设定 |
| 结果分页 | 最多 1000 条 |

库可通过 Limits 调整。宿主先检查文件字节数并使用严格 UTF-8 解码。解析目前先构造 JSON 文档，再验证记录预算；节点预算不是流式解析或内存硬配额。运行内存会明显大于文件大小，两份快照也会增加占用。超大文件分块分析不属于 v0.1。

浏览器取消会终止 Worker 并清空两份快照；这是彻底中断当前分析，之后可以重新加载。CLI 可由调用方终止进程。

## 一致性

CLI 与网页都通过编译后的同一份 MoonBit Inspector 调用。宿主代码负责 I/O、交互和展示，不重新实现 retained bytes、分组或差分算法。测试中的独立算法仅用于校验。
